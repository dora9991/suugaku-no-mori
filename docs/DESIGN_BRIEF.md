# すうがくの森 デザイン ブリーフ（Codex への依頼）

## いちばん大事なこと：ゲームらしさ

いまの試作は、カードとボタンが並んだ「アプリ」の見た目。これでは子どもは やりたがらない。
**子どもが「やりたい！」「もう1回！」と思う、ゲームの見た目と手ざわりにする**のが、この依頼の目的。

- **森の中に入る**：もり（ホーム）は、カードの一覧ではなく **森の一枚絵（シーン）**。住人4人がその中に立っていて、タップすると話しかけられる。つり場（いけ）・さぎょうだい・キャンプ・たからのちず も、ボタンの列ではなく **森の中の場所** として置く。
- **キャラクターが生きている**：住人は ふだんも少し動く（まばたき・ゆれる・ぴょこっと はねる）。おねがいは吹き出しで、文字が少しずつ出る。正解で よろこぶ・まちがいで こまる（やさしく）、の表情がある。
- **ごほうびが気持ちいい**：正解の瞬間に キラキラ・はなびら・ぴょんと はねる文字「せいかい！」と効果音。もらった素材が、かばん（もちもの）へ飛んでいく。家具ができた・なかよしアップ・どうぐレベルアップ・たからばこ は、画面いっぱいの小さなお祝い（ファンファーレ）。
- **音**：効果音（タップ・正解・おしい・かかった！・つれた・できた・レベルアップ）と BGM（森・キャンプ）。音は自作（WebAudio で合成するなど）か、ライセンスがはっきりした素材だけ。画面の上に **音の ON / OFF** ボタンを置き、選んだ設定は ブラウザに おぼえておく。
- **ゲームらしい表示（HUD）**：上のバーに プレイヤーのアイコン・ひらめきの み・きょうの もくひょう（クエストのゲージ）。数が増えるときは カウントアップする。
- **つり**：水面がゆれ、うき が ぷかぷか、かかった瞬間に「！」で しずむ。つれたら さかなが はねる。時間のゲージは色と動きで分かる。
- **つくる**：さぎょうだい の上で、家具が「ポン！」と できあがる。足りない素材が ひと目で分かる。
- **キャンプ**：芝生や土のタイルに家具を置く「はこにわ」。住人が うろうろ遊びにくる。夜は ランタンや たきびが光る。
- **画面の切りかえ**は ふわっと。ボタンは 押すと沈んで はねる。
- ただし、**問題をといている間は読みやすさが最優先**（背景や動きをおさえ、問題文・選択肢・数字キーを主役に）。不正解で怖がらせない。1つの演出は短く（1秒前後）、タップで すぐ次へ進める（演出を待たせない）。

## 前提

- このリポジトリ（suugaku-no-mori）だけを編集する。ほかのリポジトリ・フォルダは絶対に触らない（特に math-dialogue）。
- 変えるのは **見た目と演出（絵・アニメーション・音）**：
  - 色・文字・背景・ボタン・カード・アイコン・絵・アニメーション（`src/styles/`）
  - 絵（`src/ui/Art.jsx` と、新しく作る `public/art/`）
  - 画面のレイアウトと見た目（`src/screens/`・`src/ui/` の className・要素のならべ方・インライン style の見た目の部分）
  - 見た目・演出のための新しい部品（`src/ui/` に足す）や、効果音・BGM のしくみ（例 `src/ui/sound.js`）は作ってよい
  - もりのシーンのように、レイアウトを大きく作りかえてよい。ただし **ボタンを押したときに呼ぶ処理**（`act` / `go` と `src/engine/` の関数）と、その結果は変えない
  - 新しいライブラリは最小限に（使うなら README にライセンスを書く）。重い 3D などは使わない（学校の Chromebook でも なめらかに動くこと）
- **変えないもの**：
  - `src/engine/`（ルール・ごほうびの数字・セーブ）、`src/content/`（出題）、`src/data/` の id と数値
  - `src/shared/`（数学ラボ ソロからの自動同期。**ぜったいに編集しない**。`npm run sync` で上書きされる）
  - セーブのキー（`suugaku-no-mori:v1`）、画面の流れ（どのボタンで何が起きるか）、文言の意味
  - 文言は ひらがな中心のまま（小学1年生も遊ぶ）。言いまわしを整えるのは OK、漢字を増やすのは NG
- **既存のゲームのキャラクター・名前・ロゴ・UI・絵柄をまねしない**（「どうぶつの森」「ポケットキャンプ」なども）。ふんいきの参考にとどめ、すべてオリジナルで描く。

## 目指す世界観

- **森のキャンプ**：朝の光、木と布のぬくもり、手づくり感。**わくわく・元気・あたたかい**（のんびりした絵本ではなく、さわって楽しいゲーム）。
- 算数は「森で使う ことば」。**数字と記号は読みやすさ最優先**（1と7、6と9、×と＋が まぎれない書体と大きさ）。
- **まちがえても こわくない**：不正解の演出に、赤い×・大きなブザー・ゆれる画面は使わない。「おしい！」のやさしさで。正解・たからばこ・家具ができた・なかよしアップ は、うれしく。
- 夜（18時〜）はキャンプが夜の色になる（いまは `.camp.is-night`）。たき火やランタンが映えるように。

## 絵の差しかえ

- 絵は **すべて `src/ui/Art.jsx` の `ART`** に集めてある。各キー（name）を SVG／画像に置きかえれば全画面に いきわたる。**name は変えない**（画面とデータが名前で呼んでいる）。
- 必要な絵（いまの name）
  - 住人：`mugi` `chikuta` `ruru` `memo`（＋ `player`）
  - 素材：`maruta`（まるた）`ishi`（いし）`keito`（けいと）`hana`（はな）
  - つかうもの：`hirameki`（ひらめきの み＝ヒント）`sakana`（さかな）
  - どうぐ：`kago`（かご）`monosashi`（ものさし）`compass`（コンパス＝円をかく どうぐ）`mushimegane`（むしめがね）
  - 家具：`isu` `takibi` `tent` `kadan` `furin` `tako` `lantern` `telescope` `sofa` `koya`
  - 場所・しるし：`forest` `fishing` `workshop` `camp` `map` `chest` `bag` `settings` `speaker` `heart` `heartEmpty` `star` `sparkle` `party` `moon` `sun` `wave` `bobber` `away` `lock` `back`
- 置き場所は `public/art/`。**SVG を推奨**（軽い・拡大してもきれい）。画像生成を使うときは絵柄をそろえ、背景は透明、1枚 200KB 以内を目安に。
- 大きさは `size`（`xs` `sm` `md` `lg` `xl`）で指定している。絵にしたあとも この5段階を使う。
- 絵文字は残さない（OS で見た目が変わり、ゲームの絵にならない）。住人・素材・家具・場所は、すべて同じ絵柄で描きおこす。

## 読みやすさ・使いやすさ

- 端末：スマホ縦（iPhone SE の 375px 〜）、iPad、学校の Chromebook（1366×768）。どれでも横にはみ出さない。
- 文字：本文 18px 以上、問題文 22px 以上、数字キーは大きく。コントラストは WCAG AA 以上。
- タップ：48px 以上、主なボタンは 56px 以上（こどもの指）。
- 色だけで区別しない（ハートの数、ロックの形、✓ など形でも分かるように）。
- `prefers-reduced-motion` のときは動きを止める（いまの設定を残す）。キーボードのフォーカスが見えること。
- 「よむ」（よみあげ）と「ひらめき」のボタンは、問題のすぐ近くに。

## 進め方

1. `npm install` → `npm run dev` → `?demo` と `?demo=E1` と はじめから で、全画面を見る。
2. まず **「もり」のシーンと住人1人** を作り、絵柄・色・動き・音のトーンを決める。
3. デザイントークン（`src/styles/tokens.css`：色・角丸・影・文字・タップの大きさ）を決めて、全体にあてる。
4. `src/ui/Art.jsx` を絵に置きかえる（素材は `public/art/`）。
5. 各画面のレイアウト・演出・効果音を入れる（「いちばん大事なこと」の項目を全部）。
6. **`npm test` と `npm run build` が通ることを必ず確認**。公開と同じ形は `npm run build` → `npm run preview` → `http://localhost:5185/suugaku-no-mori/` で見られる。
7. 変更内容を `docs/DESIGN_CHANGELOG.md` に日本語で要約（コンセプト・全画面・各画面・素材と音の出どころ・確認したこと）。
